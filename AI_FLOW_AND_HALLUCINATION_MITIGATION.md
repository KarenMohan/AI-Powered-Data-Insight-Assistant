# AI / Data-Analysis Flow and Hallucination Mitigation

## 1. Objective

The AI assistant is designed to answer questions about the uploaded CSV dataset while minimizing unsupported or hallucinated conclusions.

The core principle is:

> Use deterministic data processing for facts and calculations, and use the language model mainly for natural-language explanation.

## 2. Processing Flow

```text
CSV Upload
    |
    v
Pandas parses the file
    |
    +--> Dataset metadata
    |
    +--> Data-quality checks
    |
    +--> Statistical calculations
    |
    +--> Aggregations / grouped results
    |
    +--> Visualization data
    |
    v
Compact grounded dataset context
    |
    v
Gemini
    |
    v
Natural-language response
```

## 3. CSV Processing

When a user uploads or reopens a dataset, the backend loads the CSV into a Pandas DataFrame.

Pandas is then used to calculate:

- Number of rows and columns
- Missing values
- Data types
- Exact duplicate rows
- Inconsistent categorical values
- Numeric summary statistics
- Category frequency information
- Grouped aggregations
- Chart-ready data

These calculations are derived from the uploaded dataset itself.

## 4. Why the Entire CSV Is Not Sent to the LLM

Sending a complete large CSV to the AI model for every question can create:

- Very high token usage
- API quota exhaustion
- Slow responses
- Context-window limits
- Increased cost
- Reduced reliability

The final approach builds a compact dataset profile locally.

For large datasets, the language model receives useful structured context rather than every raw row.

This allows the application to support larger datasets while keeping AI requests manageable.

## 5. Question-Specific Grounding

When possible, the backend identifies columns relevant to the user's question.

For example:

```text
User:
"What is the sum, average, median and mode of salary?"
```

The backend identifies the salary column and calculates the requested values directly with Pandas.

The AI receives the calculated values and formats or explains them.

```text
User Question
      |
      v
Identify relevant column
      |
      v
Pandas calculation
      |
      v
Exact result
      |
      v
Gemini explanation
```

This means the LLM does not need to calculate the statistic from memory or estimate it.

## 6. Visualization Grounding

Charts are not generated from invented AI values.

The backend calculates chart data directly from the active DataFrame.

The frontend renders this data with Recharts.

```text
CSV
 |
 v
Pandas aggregation
 |
 v
JSON chart data
 |
 v
Recharts
```

When the user asks the chatbot to explain a generated chart, the chart's actual data is included as context so the explanation is grounded in what is displayed.

## 7. Preventing Hallucinated Answers

### Dataset-only instruction

The chatbot prompt explicitly instructs the model to answer only using supplied dataset context.

### Exact Pandas calculations

Where numerical calculations are required, Pandas is treated as the authoritative source.

### Compact factual profile

The model receives actual column information, distributions, statistics, and selected sample information rather than relying on general knowledge.

### Unrelated-question handling

Questions unrelated to the uploaded dataset are rejected with a dataset-specific response instead of allowing the model to answer from general knowledge.

### Insufficient-context handling

If the available grounded context cannot support an answer, the model is instructed to say that the available dataset information is insufficient rather than inventing an answer.

### Local fallback

If the external AI model is unavailable or rate-limited, the backend can still return certain deterministic results generated by Pandas.

This improves reliability and ensures that simple analytical questions do not completely depend on the external AI service.

## 8. Streaming Responses

The chatbot uses response streaming so users begin seeing an answer before the complete response has been generated.

This improves perceived responsiveness without changing the grounding mechanism.

## 9. AI Service Availability

External LLM APIs may occasionally return rate-limit, quota, or temporary service-unavailable responses.

The application handles these conditions gracefully and can fall back to local Pandas-based responses for supported analytical questions.

## 10. Trade-Offs

The compact-context approach improves reliability and scalability, but it has a limitation:

> The AI does not receive every raw row of a large dataset.

As a result, highly specific row-level questions may require additional deterministic backend analysis.

A production version could extend the analytical router so more question types are calculated automatically before calling the LLM.

## 11. Summary

The application deliberately separates responsibilities:

```text
Pandas   -> factual data processing and calculations
Gemini   -> natural-language interpretation and explanation
Recharts -> visualization rendering
MySQL    -> persistent user and dataset storage
```

This architecture reduces hallucination risk because important numerical results originate from the actual uploaded dataset rather than from the language model's general knowledge.
